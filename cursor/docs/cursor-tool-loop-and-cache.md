## 工具循环防护

硬停止现在是**按账户显式启用的工具策略，默认关闭**。未配置、`null` 或空名单不会硬停止任何工具，包括 `todowrite`；因此正常轮询、重复追加等工作流可以继续向模型请求结果或总结。

只有账户管理者确认某工具适合该限制时，才在对应 Cursor OAuth 认证 JSON 中添加以下字段（保留原有凭据和其他字段）：

```json
{"tool_loop_guard_tools": ["todowrite"]}
```

该示例只是选择一个工具名，不代表插件能证明该工具幂等或没有进展。工具名区分大小写、精确匹配，不进行空白裁剪，也不支持通配符、前缀或自动内置名单。不要把需要等待状态变化的轮询工具或有累积副作用的工具加入名单。选择某工具即接受它连续三次相同返回后可能连最终总结也被阻止的限制。

配置保存在认证 JSON，不是聊天请求参数；客户端在 chat payload 中提供同名字段不能启用或覆盖账户策略。配置会随认证解析、序列化及 token 刷新保留；本次不增加管理页控件，也不修改已运行账户的配置。删除该字段或设为空数组即可关闭该账户的硬停止。

插件在流式、非流式共同的请求解析入口，针对名单中的工具检查历史末尾的三个连续工具回合。只有同时满足以下条件才硬停止：

- 每回合是一个 assistant 工具调用与其紧随的 tool 结果，结果非空。
- 三次调用 ID 各不相同，且每个结果都明确关联对应调用；显式结果名称不得冲突。
- 工具名、参数和结果均相同。JSON 对象键序、格式空白不会绕过判定，数字字面量不转换为浮点数。
- 中间没有新的 user 指令、不同工具、不同参数或不同结果。

assistant 随工具调用附带的重复说明不是实际工具进展。空 assistant 占位消息仍由原有解析逻辑过滤。

触发后插件在启动流和请求 Cursor **之前**返回 `cursor_tool_loop_detected`，HTTP 状态提示为 400，`retryable=false`（ABI JSON 会省略值为 false 的字段）。错误会说明这是已配置策略的限制，而非对工具无进展的确定性判断。不会伪造成功回答、重放缓存工具调用或估算一次未发生的模型请求。新的明确 user 消息允许继续；也可从账户名单移除该工具，无需清理会话缓存。

这是可选的有限重复检测，不是完整防循环或费用上限保证。若错误地将轮询/累积写入工具加入名单，仍可能误拦截。多工具批次、调用关联不明确、分离的 assistant 消息打断序列等情况不会仅凭相似文字拦截。历史被客户端改写、压缩或插入新 user 消息后，本保护不保证识别此前的循环。

防护不保存跨请求计数或工具结果缓存，不会把一个请求的拦截状态传播给其他账户、模型、会话或后续请求。

## 缓存优化

1. **内容分块等价性**：连续文本块按现有 prompt 的换行拼接规则规范化。例如 `"a\nb"` 和两个文本块 `"a"`、`"b"` 使用相同历史摘要，避免客户端更换内容表示形式造成检查点误失效。不会删除空白、重排工具目录、合并跨图片/附件的文本，或忽略调用 ID、媒体内容和历史顺序。
2. **增量历史摘要**：请求解析时保留摘要链末端。确认 assistant 输出时只对新输出追加摘要，不再重新序列化和散列完整历史。该操作不修改原始 transcript 或已计算的前缀摘要。

沿用原有安全边界：账户 + 模型 + 稳定会话隔离、精确历史前缀和 system 校验、15 分钟 TTL、64 条 / 16 MiB 上限、并发 generation 防护，以及无输出且符合条件时最多一次的完整重放回退。

本次没有缓存或跳过实际文件读取、shell、轮询等工具执行，没有复用 assistant 的工具调用响应；未把待回填的工具检查点提升为已确认状态，也没有实现未经验证的原生 MCP 结果注入或跨 Run KV blob 复用。

## 首轮本地验收（2026-09-12，策略修复前）

以下记录为首轮缓存/检测器实现的历史验收；当时的全工具默认硬停止已被上述显式策略替代，不能用旧结果证明默认配置仍会拦截。

- 回归先红后绿：原实现会把三个重复工具回合继续发往上游；新实现流式、非流式均同步拦截且上游调用数为零。
- 覆盖参数/结果改变、新 user 指令、调用 ID/名称关联、JSON 键序/空白、大整数精度、空 assistant 占位，以及拦截后继续请求。
- 内容分块回归先红后绿，并验证模型/system/工具/媒体/顺序/数值变化的原有失效测试不被削弱。
- 实际 macOS arm64 C 动态库 ABI：注册、无效 JSON、流式与非流式循环错误均符合预期。
- 真实 Cursor HTTP 客户端 + 本机隔离 HTTPS/HTTP2 Connect 假上游：长历史的初次请求 94,528 字节，等价分块续轮 343 字节；跨账户、跨会话均完整重放；新 user 指令可继续。
- 约 1.1 MiB 合成文本的十轮微基准：追加 assistant 摘要从 1.305–1.528 ms/op 降为 0.847–1.394 µs/op，新实现为 560 B/op。仅代表该本地步骤，不是模型端到端延迟或账单 Token 节省。
- 全量 `go test -race -shuffle=on -count=1 ./...`、`go vet ./...`、动态库构建通过；修改的两个 Go 包语言诊断无错误。

这些结果使用合成数据，不包含用户会话外传。没有修改 OpenCode、CPA、生产配置或运行数据；未执行生产复杂会话验收，也未构建或发布新的 Linux amd64 Release。
