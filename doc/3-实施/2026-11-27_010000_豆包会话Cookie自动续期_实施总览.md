# 实施总览：豆包插件会话 Cookie 自动续期

## 当前计划最终方案的简要说明

把扣子插件已验证的「会话双向续期」能力移植到豆包插件：用当前会话 Cookie 调令牌端点换新令牌，再用新令牌换回一批新会话 Cookie，叠加写回账号文件；由插件自建 4 小时定时器驱动（启动即跑一轮），失败退避、真失效标记。主落点是新增 `doubao/renew.go` 与 `doubao/renew_loop.go`，改造 `tokenbeat.go` 的端点调用；之所以复用豆包已有的 `durableJar` 承载写回，是因为它已具备 Cookie 叠加与防覆盖闸门，避免整份照搬扣子的 `cookieStore`。

## agent 对当前问题的理解

- **问题 / 目标**：豆包插件的自动续期只换 msToken，从不续会话 Cookie，导致所有账号按会话寿命陆续过期（号10 首发）。目标是让会话 Cookie 定时自动滚动，账号不再自然过期。
- **本轮计划范围**：双向换发、换发判据、Cookie 叠加写回、定时驱动 + 失败退避、会话失效标记与告警、版本与发布。
- **不在范围**：无凭据自动登录（真失效仍需重新授权一次）；抢救已过期的号10；其它插件。
- **当前优先闭环**：先实现换发内核 + 判据 + 写回并通过本地单测，再接定时器，最后发布热重载取证。
- **关键假设 / 已验证前提**：豆包端点双向契约已生产实测成立（活账号拿 token 355 + 9 条 Set-Cookie）；号10 的端到端验证以其重新授权为前提，列为收尾交接项。

## 实施周期与最小任务

### CYCLE01：会话双向换发内核

- **目标**：实现「Cookie→token→Cookie」换发 + 会话主项判据 + 叠加写回，纯逻辑闭环。
- **进入条件**：Bug 主文档与修复建议已落盘（已完成）。
- **最小任务 T1.1**：改造 `doubao/tokenbeat.go` 的 `doTokenBeat`，支持带 Cookie 调用并从响应头读 `x-tt-token`（参照 `coze/credentials.go:119`）。产出：`doTokenBeat(token, cookieHeader)` 返回响应体、Set-Cookie、新 token、错误。验证点：单测覆盖「带 token 换 Cookie」「带 Cookie 换 token」两种入参形态。
- **最小任务 T1.2**：新增 `doubao/renew.go`，实现 `rotatedSessionCookies`（会话主项值变化判据，参照 `coze/credentials.go:283`，doubao 会话名用 `isSessionCookieName`）、`mergeSessionCookies`（基于 `durableJar` 叠加合并，参照 `coze/credentials.go:265`）、`renewSession`（两步换发 + 形态 A/B 判据）、`applyRenewal`（外部替换闸门 `replacedLocked` + 写回）。产出：`renew.go` + `renew_test.go`。验证点：单测覆盖真换发成功、死会话只下发埋点 Cookie 不记成功、Cookie 叠加不丢会话、外部替换放弃写盘。
- **收口条件**：`python scripts/cgo-shim-build.py doubao` 全绿 + 哨兵反证有效 + 6-review STYLE: PASS。
- **停止条件**：任何门禁 FAIL 即停，不进入下一周期。

### CYCLE02：定时驱动与配置接入

- **目标**：让换发内核按 4 小时周期自动运行，启动即跑一轮，失败退避，热重载旧的定时器随实例停止。
- **进入条件**：CYCLE01 收口。
- **最小任务 T2.1**：新增 `doubao/renew_loop.go`，实现 `renewLoop`（启动等待宿主就绪 → 立即一轮 → 按 `renew_interval_seconds` 周期）、并发上限、失败退避、实例守卫（复用 keepalive 的 cancel/done 实例句柄，热重载 stop 时一并停）。产出：`renew_loop.go` + `renew_loop_test.go`。验证点：单测覆盖启动即跑、周期触发、失败账号退避不影响健康账号、停止后不再跑。
- **最小任务 T2.2**：`doubao/main.go` 的 `Config` 增加 `renew_interval_seconds`（默认 14400）+ ConfigField 声明，启动/reconfigure 时重建 renew 定时器（与 `restartKeepalive` 并列）。产出：`main.go` 改动 + 配置字段单测。验证点：配置读不到用默认值、配置变更触发定时器重建。
- **收口条件**：cgo-shim 全绿 + 哨兵 + 6-review。
- **停止条件**：定时器与 keepalive 实例句柄冲突导致双启则停。

### CYCLE03：失效标记与面板状态

- **目标**：会话真失效时面板显示「需重新授权」而非「ok」，避免误导。
- **进入条件**：CYCLE02 收口。
- **最小任务 T3.1**：`doubao/management.go` 的 `authStateOf` 增加服务端失效标记字段（账号文件新增 `auth_invalid` 字段，续期拿到 `session_expired` 时置位），面板账号状态据此返回「需重新授权」。产出：`management.go` 改动 + `authfile.go` 字段 + 单测。验证点：标记置位时状态为需重新授权、续期成功后清除。
- **收口条件**：cgo-shim 全绿 + 哨兵 + 6-review。

### CYCLE04：发版与生产热重载取证

- **目标**：新版本上线生产并验证会话续期真实生效。
- **进入条件**：CYCLE01~03 全部收口。
- **最小任务 T4.1**：bump `VERSION` 与 `main.go` 的 `version` 0.1.39→0.1.40，CHANGELOG 加节，commit/push → dispatch CI → 下载资产 → publish-assets → registry → 远端 raw 验证。
- **最小任务 T4.2**：生产 `plugin-store install` 热重载，验 `hot reloaded active_version=0.1.40`、落盘 .so sha256 与 release zip 一致、13 插件启用态 `STATE_UNCHANGED`、容器未重启。
- **最小任务 T4.3**：用活账号（欧皇小德子等）验证会话 Cookie 指纹随续期轮次变化；号10 待用户重新授权后补验。
- **收口条件**：热重载生效 + 会话指纹变化 + 启用态零漂移。

## 主要风险与反方批判

- **反方结论**：方案假设成立，推荐路线保留；需补一条硬约束再放行。
- **批判 1（假设挑战）**：若豆包第一步就下发会话 Cookie（形态 A），第二步无需再打；实现必须同时兼容形态 A/B，否则在某个上游行为下会误判「未换发」。已对策：`renewSession` 双形态判据。
- **批判 2（边界与异常）**：死会话打 beat 仍下发埋点 Cookie（实测号10 曾 9 条），按条数判成功会掩盖失效。已对策：`rotatedSessionCookies` 锚定会话主项值变化。
- **批判 3（回滚与失败代价）**：热重载后旧实例的 renew 定时器若不停，会用旧 Cookie 覆盖新实例续好的凭据。已对策：定时器实例句柄随热重载 stop；叠加 `replacedLocked` 外部替换闸门。这是必须验证的高风险点。
