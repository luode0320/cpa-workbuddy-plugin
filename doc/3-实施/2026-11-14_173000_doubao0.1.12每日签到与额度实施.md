## 1. 当前方案的简要说明

在 `doubao` 插件内新增签到与额度能力：面板新增「今日签到与免费额度」区块与「今日签到」按钮；后端新增两个只读/写一次的管理路由 `/checkin/status` 与 `/checkin/run`；每日 `10:00` 与 `22:00` 各跑一轮自动签到。真正的写请求被 `chosen_type` 渠道闸门与「已签即跳过」双重前置挡住，单账号每日最多一次提交，失败即停。

主落点是新建的 `doubao/checkin.go`（接口调用、状态判定、额度递归提取、定时器），`protocol.go` / `models.go` / `completion.go` 零改动——19 键网页端 query、`endpointURL`、`SamanthaDoubao` UA、`postBusinessJSON` 全部现成可复用。

## 2. 问题与目标

- **问题**：豆包「免费用豆包工作」活动每日可领 200 活动额度（周一翻倍、30 天累计上限 8800），但插件此前完全没有签到能力（`doubao/` 下 grep `checkin|签到|campaign|quota` 零命中），只能靠用户手工点。
- **目标**：让面板能看见每个账号今日的签到状态与活动赠送额度，并在平台允许的渠道上自动完成签到；平台改投桌面端的账号如实上报而不做无效写请求。
- **本轮范围**：签到状态查询、活动赠送额度查询、条件签到、手动触发、每日两轮定时、面板展示。
- **非范围**：桌面端 CDP 自动点击（档 3，插件跑在无桌面的 Linux 容器内不可行）、任务奖励自动领取、`a_bogus` / `biz_params` / `AgwCommonParam` 等风控字段伪造。

## 10. 阶段 14 结论：chosen_type=3 无法由插件侧绕过（2026-11-14 终局定性）

用户原始诉求是「用插件解决全部问题」，即在插件内把 11 个被平台改投桌面端的账号也签上。本轮把所有可行路径穷尽并留下取证：

### 10.1 已证伪的路径（逐条）

| 方向 | 覆盖范围 | 结果 |
|---|---|---|
| 渠道号切换 | aid = 497858 / 582478 / 1044603 × doubao_device_platform = web / desktop × web_platform / client_platform / runtime 组合 | chosen_type 恒 3；landing/checkin 恒 710010702。aid=1044603 仅能把落地页按钮从「下载桌面端」换成「立即签到」，不改变 chosen_type |
| 设备指纹 | 换随机 device_id / web_id / tea_uuid / fp / web_tab_id、用另一账号的设备、完全省略 | 全部无效；chosen_type 是账号属性不是指纹 |
| 版本号 | version_code = 20800 / 23001 / 23010 / 23206 / 23305 / 23519 / 23611；pc_version / doubao_pc_version / runtime_version 同步改 | 全部无效 |

### 10.2 决定性证据

真实客户端进程内 Input.dispatchMouseEvent 点击平台自己的「立即签到」按钮（x=817,y=255,w=80,h=36），Network.enable 抓到的完整请求与响应：

- 请求 query 含 aid=497858&real_aid=497858、web_id=7707944846640416256、tea_uuid=7707944846640416256、doubao_pc_version=5.74.95、runtime=web、真实 msToken、真实 a_bogus；头含 Agw-Js-Conv: str、Referer: https://www.doubao.com/pc/agent-explore；body {"scene":"pc_incentive_task_mvp_v3"}。
- 响应：{"data":null,"code":710010702,"msg":"系统错误","message":"system error","error":{"code":710010702,"message":"系统错误","locale":"zh"}}。
- 点击后页面仍是「立即签到 / 累计获得额度：0 点」；回查 v3/detail → checked_in_today=false、task_status=1、progress.total_amount=0。

对照组：同批裸 HTTP 请求下账号 欧皇小德子 能正常签到（幂等回执 checked_in=true / reward_amount=200），证明裸 HTTP 通道本身未被封，拒绝点在账号维度。

### 10.3 定性

**710010702 是平台按账号投放策略的拒绝，不是请求构造、签名、渠道、设备指纹或页面上下文问题——平台自身前端 + 真实签名 + 真人可信点击同样失败，且失败后服务端状态零变化。插件侧没有任何可复刻的成功路径。**

因此 11 个 desktop_only 账号无法通过本插件签到；插件能做的是如实展示状态（平台限桌面端）并完全不发无意义写请求，而不是反复裸提交或引导用户去做同样失败的桌面端点击。

### 10.4 保留的降级行为

- chosen_type != 0 时不请求活动详情、不提交签到写请求（TestRunCheckinSkipsDesktopChannel 与 TestCheckinStatusForDesktopAccountIgnoresDetailError 双用例锁死）。
- 额度展示对 desktop_only 账号返回空数组，面板显示「暂无赠送额度」。
- 若平台未来把某账号改回网页渠道，chosen_type 会自然变 0，插件无需改代码即可恢复自动签到。
