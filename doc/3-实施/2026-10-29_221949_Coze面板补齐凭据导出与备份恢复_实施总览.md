# Coze 面板补齐凭据导出与备份恢复_实施总览

- 日期：2026-10-29
- 关联需求：`doc/2-需求/2026-10-29_221949_Coze面板补齐凭据导出与备份恢复需求.md`
- 目标插件：`coze-provider` 0.6.4 → **0.7.0**

## 0. 当前计划最终方案的简要说明

在 `coze` 插件内新增一对备份接口（`GET /export`、`POST /import-cred`）与面板对应入口，复用既有的 `listAllAuthFiles` / `writeAuthFileDirect` / `reRegisterOneToHost` 三段现成通道，不改动授权、续期、积分任何链路。这样做是因为 coze 与兄弟插件的差异只在凭据形态（Cookie 会话），落盘与宿主注册逻辑已经完全具备，新增代码只需负责「汇总成文件」和「拆回来再落盘」。

## 1. 问题与目标

coze 面板缺少导出与导入能力，账号无法备份与迁移。目标：补齐与其余 8 个插件等价的备份能力，且恢复后账号行为与备份前完全一致。

## 2. 本轮范围

### 做

- 后端 `GET /export`（导出全量凭据明文）
- 后端 `POST /import-cred`（逐条恢复）
- 面板「导出备份」「导入备份」按钮 + 导入弹窗
- 路由注册、CHANGELOG、README、VERSION / main.go 版本号
- 单元测试 + 前端回归测试

### 不做

- 不新增「粘贴 Cookie 新增账号」入口（用户裁定）
- 不改授权、续期、积分巡检、低额禁用任何链路
- 不改其他 8 个插件
- 不改宿主管控配置

## 3. 非范围与前置约束

- coze 无 PAT / API Key 体系，导入只能走备份恢复
- 备份文件含 Cookie 明文，属凭据文件，不入库、不进 Git
- 管理接口鉴权沿用宿主中间件（coze 现状即如此，不新增插件层密钥）

## 4. 关键假设与待确认点

| 项 | 结论 |
|---|---|
| 恢复落点 | 固定在插件账号目录 `~/.antigravity_cockpit/coze_accounts/<auth_id>.json`，与 `saveFromToken` 同口径，天然幂等 |
| 宿主注册 | 显式调 `reRegisterOneToHost`；不依赖 `writeAuthFileDirect` 的自动分支（后者见到 `PhysicalPath` 非空会跳过） |
| 注册失败语义 | 不整体判负，回 `registered:false` + `warning` + warn 日志 |
| 禁用账号恢复 | 保留 `disabled`，且照样推宿主（spool 需存在该条目并带标记） |

## 7. 任务完成条件

上述测试全部通过，代码格式（gofmt）干净，文档落盘。

## 8. 任务停止 / 结束条件

出现需要改动授权 / 续期 / 积分链路，或需要改宿主侧配置时停止并回到需求确认。

## 9. 最大推进边界

只改 `coze/` 与 `test/coze/` 与 `doc/`；不做发布、不动生产、不改其他插件。

## 10. 已知限制

- 导出文件为完整明文凭据，持有文件等于持有账号，需自行保管
- 面板 `exportAuth` 走前端 Blob 下载，需要浏览器允许下载（iframe 嵌入场景依赖宿主面板的下载策略）
- 恢复仅重建凭据，不回填积分快照；积分需等下一轮巡检（默认 1 小时）才有数据
