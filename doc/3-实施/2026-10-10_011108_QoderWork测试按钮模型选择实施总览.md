# QoderWork 测试按钮模型选择实施总览

结论：把 qoderwork-provider 面板从「没有测试入口」补齐为「点卡片『测试』→ 弹出该账号可用模型小窗口 → 点选指定模型 → 发一次真实推理测试」；影响：qoderwork 面板交互与后端新增两条管理路由；范围：qoderwork/panel.html、qoderwork/active_ping.go（新增）、qoderwork/models.go、qoderwork/management.go、单测与前端 vm 回归脚本；非范围：不引入定时自动探活（watchdog）、不改宿主 ABI、不改 CN 签到与保号链路、不触碰 cursor/ 与其它插件；变化：新增只读 GET /models 与 POST /test-active，面板新增测试弹窗；完成标准：qoderwork cgo-shim build/vet/test 全绿、面板 vm 回归全绿（含旧版反证）、6-review STYLE PASS、版本 bump 与 registry 同步。

## 当前计划最终方案简要说明

- 推荐方案一句话结论：新增只读管理路由 `GET /plugins/qoderwork-provider/models?auth_index=<idx>` 返回该账号可用模型列表；新增 `POST /plugins/qoderwork-provider/test-active`（body `{auth_index, model?}`）发起一次真实推理测试；前端「测试」按钮改为打开模型选择弹窗、点选后带 model 调 /test-active。
- 主落点 / 主路径：`qoderwork/management.go`（新增两条路由 + 注册 + switch case）、`qoderwork/active_ping.go`（新增：手动测试发送链路 + handleTestActive）、`qoderwork/models.go`（新增账号级模型列表 helper）、`qoderwork/panel.html`（测试弹窗 + 卡片按钮 + JS）。
- 为什么先走这条路线：与既有 `callModelsAPI`、`endpointChat`、`applyCosyHeaders`、`qoderEncode`、`buildQoderBody` 完全同源复用，零新增依赖，改动最小；对齐 workbuddy 已收口的同族做法，避免出现两套并行路径。

## Agent 对当前问题的理解

- 问题 / 目标：qoderwork 面板当前没有测试按钮，用户无法手动验证某个具体模型是否可用；需要新增「测试」按钮，点击后弹出该账号支持的模型小窗口，点选指定模型后进行测试。
- 本轮范围：qoderwork 插件的测试按钮交互、/models 与 /test-active 接口、单测与前端 vm 回归、版本与发布收口。
- 非范围：定时自动活跃探测（watchdog）保持不引入；不改宿主核心、不改 cursor/、workbuddy/、workbuddy-ai/、traework/；不改其它按钮。
- 当前优先闭环：CYCLE-01 后端 /models 接口 + /test-active 指定模型参数 + 单测全绿。
- 关键假设 / 待确认点：模型列表来源复用 qoderwork 既有动态发现链路（`callModelsAPI`）；本地无真实账号凭据，真实上游模型拉取在生产验收；本地用 vm 回归验证契约与交互。
- unresolved_decisions：无 P0 或 P1 决策。
