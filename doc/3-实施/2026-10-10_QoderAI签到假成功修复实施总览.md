# Qoder AI 签到假成功修复实施总览

## 当前计划最终方案的简要说明

先修宿主桥状态码解码（把 workbuddy 已验证的 `parseHostHTTPDoResult` 移植到 qoder-ai），再收紧签到响应归一化，让 404/4xx/5xx 不再被当作成功；这是所有依赖 `StatusCode` 判定的链路（签到、动态模型、额度、计划、探活）的共同根因。随后用生产账号真实复验：修好解码后签到会如实返回失败，因为国际版 OpenAPI 没有签到端点（GAP-001），真实签到入口需产品确认，本轮不伪造成功。

## agent 理解的问题 / 目标

- 问题：生产账号 u8e6a5348 / ua554edc3 签到显示「成功 +100」但积分不变。
- 目标：定位并修复根因；若判定为上游环境性阻断，则按契约透传真实结果并登记 GAP，不伪造成功。

### 本轮计划范围

- qoder-ai 宿主桥非流式响应解码、签到响应归一化。
- 生产账号真实复验与根因证据固定。

### 不在范围

- 推理链路、模型映射、SSE 转发、账号调度与生命周期、宿主 ABI。
- qoderwork（同源缺陷，另案跟踪）。

### 当前优先闭环

单账号签到链路：取证 → 根因 → 修复 → 本地全绿 + 反证 → 生产真实复验。

### 关键假设 / 待确认点

- 假设签到失败是插件侧可修复问题；实测证明国际版 OpenAPI 无签到端点，属产品事实，需确认（GAP-001）。
