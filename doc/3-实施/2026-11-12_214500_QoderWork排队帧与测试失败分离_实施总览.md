# QoderWork 排队帧与测试失败分离 实施总览

**当前计划最终方案的简要说明**：在错误成型层把「上游容量排队」从「账号/凭据故障」里拆出来——`policy.go` 负责把排队帧解析成结构化信息，`active_ping.go` 用专用错误类型承载并把可读中文提示与结构化字段交给面板，`panel.html` 增加「排队中」第三态。选这个落点是因为诊断已确认：排队判定（`isQueueFrame`）与 failover 拦截（`recordAccountFailure` 的 `return false`）本来就正确，缺陷只发生在「识别之后语义没往上传」这一段，改动面因此限定在三个文件、零逻辑分支改动。

## 1. agent 对问题的理解

- **问题/目标**：面板「测试」按钮对 `Qwen4-Max-Preview` 报 `活跃测试失败 ... upstream 200: 403: 10605: {...isQueued:true...}`。该帧 `errorCode:0`、`serviceAvailable:true`、`subCode:RESOURCE_LIMIT`、`retryAfterSeconds:60`，是上游容量排队而非账号故障。目标：让排队在用户态显示为「排队中 + 稍后重试」，账号类失败保持原样。
- **本轮范围**：`qoderwork/policy.go`（结构化解析）、`qoderwork/active_ping.go`（排队错误成型 + 结果 map）、`qoderwork/panel.html`（三态渲染 + 两条 warn 样式）、新增同包测试 `qoderwork/active_ping_queue_frame_test.go`、版本 0.13.16 → 0.13.17 与 CHANGELOG、`doc/` 三份文档。
- **非范围**：排队判定阈值、failover 计数/冷却/禁用逻辑、自动等待重试、上游排队策略、`workbuddy` 系探活（其只读首包 512 字节判成功属另一问题）。
- **当前优先闭环**：面板点「测试」→ 命中排队 → 黄色「排队中」+ 中文提示 + `retry_after_seconds` → 用户稍后重试；非排队失败一字不改。
- **关键假设/待确认点**：`queueFrameError.Error()` 保持 canonical 文本（历史日志对照需要）——已由测试 `TestQueueFrameErrorKeepsCanonicalText` 锁定；结果键用 `upstream_queued` 以避开既有的「后台刷新排队数」`queued` 语义。

- 7 个新测试全绿，且哨兵/变异反证均按预期失败后复原。

- 生产面板对同一排队帧显示「排队中」黄色态与中文提示；非排队失败仍显示「测试失败」。

## 7. 任务停止/结束条件

- 若上游已不再返回 10605 排队帧，生产实测只能验证「不回归」（正常成功仍显示成功），不能验证排队呈现——此时以单测证据为准并如实记录。
- 若开发容器无法拉取新版本 .so，发布链路停在 CI 产物验证并如实记录环境阻断，不伪造热重载结论。

## 8. 最大推进边界

本轮只推进到 `qoderwork-provider` 一个插件；`qoder-ai` / `qwenwork` 同族同步不在本轮执行（结构已确认同构，留待独立轮次）；不重启生产 `cli-proxy-api` 容器。
