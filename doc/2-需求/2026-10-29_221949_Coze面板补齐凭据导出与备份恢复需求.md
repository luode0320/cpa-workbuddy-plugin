# Coze 面板补齐凭据导出与备份恢复

- 日期：2026-10-29
- 状态：需求已确认，进入实施
- 来源：用户当轮指令「coze插件好像面板不能导出, 导入账号, 缺少了这个功能。」
- 影响插件：`coze-provider`（本轮只做这一个）

## 1. 现象与实测证据

用户反馈 coze 插件面板缺少导出与导入能力。2026-10-29 只读核对结果：

| 检查项 | coze | 其余 8 个插件 |
|---|---|---|
| `panel.html` 出现「导出/导入/export/import」 | **0 处**（46,864 字节 / 927 行） | 全部命中 |
| 后端 `/export` 路由 | **无** | workbuddy / zcode / qoderwork / qoder-ai / qwenwork / traework 均有 |
| 后端 `/import` 或 `/import-cred` 路由 | **无** | 同上 |

`coze/management.go:70-82` 的路由注册表只有 `accounts / login-start / delete / enable / disable / renew / models / test-active / credits / refresh-all / claim-daily / register-host` 十一条，确实不存在备份类接口。这是功能缺失，不是 Bug 或回归。

## 2. 与兄弟插件的关键差异

coze 没有 PAT / API Key 体系：账号唯一来源是「浏览器扣子登录 → 一次性 x-tt-token → token beat 换会话 Cookie」（`coze/credentials.go` 头部注释）。落盘结构因此是 Cookie 型：

```
{type, provider, auth_id, cookie_header, sec_user_id, user_id, screen_name,
 mobile, cookies[], login_at, last_renew_at, auth_invalid, label, disabled,
 low_credit_disable, low_credit_disable_below, low_credit_disable_at,
 created_at, updated_at}
```

因此导入路径不能照搬 workbuddy / zcode 的「粘贴 Token 换票」，只能走「备份原样恢复」。

## 3. 需求

### 3.1 功能

1. **导出备份**：面板新增「导出备份」按钮，把全部 coze 账号落盘凭据导出为单个 JSON 文件并下载。
2. **备份恢复**：面板新增「导入/恢复」入口，接受导出文件、凭据数组或单条凭据，逐条恢复落盘并注册宿主。
3. 导出/恢复必须保留完整状态：`disabled`、`label`、`auth_invalid`、三个低额禁用归属标记、`login_at` / `last_renew_at`，使灾备恢复后账号行为与备份前一致。

### 3.2 用户已裁定的边界（2026-10-29）

| 议题 | 裁定 |
|---|---|
| 导入范围 | **仅备份恢复**；不新增「粘贴 Cookie 换号」入口，新账号仍走浏览器授权 |
| 导出内容 | **完整明文凭据**（`cookie_header` + `cookies[]` 原文），文件可直接回导；口径与 8 个兄弟插件一致 |
| 覆盖插件 | 只改 `coze-provider` |

### 3.3 非范围

- 不新增 Cookie 粘贴新增账号入口（用户明确排除）
- 不改浏览器授权、续期、积分巡检、低额禁用任何现有链路
- 不改其他 8 个插件
- 不改宿主管控配置

## 4. 验收判据

| 步骤 | 判据 |
|---|---|
| 单测 | 覆盖导出结构、单条/数组/包装三种恢复形态、非法凭据拒绝、`auth_id` 缺失时按 `sec_user_id` 重算、禁用账号恢复后仍禁用 |
| 本地构建 | `python scripts/cgo-shim-build.py coze` build / vet / test 全绿 |
| 导出实测 | 生产面板点「导出备份」，文件内 `count` 与实际账号数一致，`cookie_header` 非空 |
| 恢复实测 | 用该文件恢复到同一实例，账号数、`label`、`disabled` 与备份前一致，宿主认证文件页可见 |
| 无回归 | 未触发导出/导入时面板全部既有按钮、账号列表、积分巡检行为不变 |

## 5. 与既有结论的关系

- 复用 `coze/authfile.go` 的 `listAllAuthFiles` / `writeAuthFileDirect` / `isSafeCozeAuthPath`，不新增落盘通道
- 复用 `coze/register_host.go:76` `reRegisterOneToHost` 的两步法（本地写盘 + 宿主注册），避免 `writeAuthFileDirect` 在 `Disabled=true` 时不注册宿主的死角
