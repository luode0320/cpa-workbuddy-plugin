# DSH 客户端 `@` 文件引用段触发 11128：根因与修复（workbuddy 0.21.23）

- 日期：2026-11-10
- 影响面：workbuddy-provider CN 账号链路（copilot.tencent.com）；Global 账号不受影响
- 结论：DSH（DeepSeek-Harness）内核注入的 `@` 文件引用说明段会被上游通道校验命中，
  与账号、域名、请求头、并发无关；插件侧按角色中和锚点即可恢复。

## 1. 现象

DSH 客户端接入本插件的 CN 账号池后，每轮第一条消息稳定失败：

```
400 {"code":11128,"msg":"Illegal API invocation from an unapproved channel",
     "displayMsg":{"zh":"请求被拦截，请重新发送"}}
```

既有品牌词改写（0.21.20 上线，`DeepSeek Harness` → `DeepSeek-Harness`）只能覆盖
身份句，无法覆盖文件引用段，因此该路径仍整轮不可用。

## 2. 一手证据（真实 CN 账号直连上游消融）

方法：同一 token、同一套请求头、同一 endpoint，唯一变量是消息内容与角色；
user 消息填充 2000 字符以满足「请求体 >1KB 才稳定触发」。

| 实验 | 内容 | 结果 |
|---|---|---|
| A | 干净 system | 200 |
| B | system 含完整 FILE_REFERENCE_PROMPT | **400 / 11128** |
| C | `You are a coding agent powered by ...` | 200 |
| D | `... through the DeepSeek Harness Web GUI ...` | 200 |
| E | 零宽身份句 `DeepSeek\u200b Harness` | **400 / 11128** |
| F | 整段 `@` → `(at)` | 200 |
| G | 仅锚点 `Tokens prefixed with @` → `(at)` | 200 |
| H | 身份句连字符化 `DeepSeek-Harness` | 200 |
| I | 身份句前置一行普通文字（不在开头） | 200 |
| J | FRP 放在 assistant 消息 | **400 / 11128** |
| K | FRP 放在 user 消息 | 200 |
| L | 锚点拆词 `with` → `by` | 200 |
| C2/D2/D3/D4 | coding agent / Web GUI 句放中段、尾部、单句 | 全 200 |

结论：

1. 必须处理的是**文件引用段**（`@`）与**身份句**（已由品牌词规则覆盖）。
2. 上游只扫 `system` / `developer` / `assistant`；`user` / `tool` 不扫。
3. assistant 里每一条都会被查，只改第一条无效。
4. 最小介入即可：只换锚点里的 `@`，段落其余内容原样保留。
5. 社区方案里的 `coding agent powered by` / Web GUI 整句改写，在当前上游复测不触发，
   因此不引入 —— 无证据的改写只会改变模型自我认知。

## 3. 根因

上游对消息做**词组级**内容风控：`Tokens prefixed with @` 这一串连续词 + `@` 字形
构成指纹，命中即整请求 400。该判定与请求头、账号、并发无关，属于内容通道校验。

既有实现只在「品牌词」维度做改写，缺少「文件引用段」维度，且未按角色区分扫描面。

## 4. 修复（0.21.23）

- `keyword_neutralize.go`
  - 新增 `dshFileReferenceAnchorRe`：`(?i)(Tokens)\s+(prefixed)\s+(with)\s+@`
    → `${1} ${2} ${3} (at)`。
  - 新增 `scannedFingerprintRoles`（system / developer / assistant）。
  - 新增 `neutralizeForRole`：通用规则对所有角色生效；文件引用段规则只对扫描角色生效。
  - 新增开关 `dsh_fingerprint_neutralize`（默认开启），配置变更留痕。
- `payload.go`：`rewriteContentField` 读取 `role` 后按角色分派；字符串与数组 text part 同规则。
- `usage_config.go`：解析并热应用开关。
- `main.go`：面板新增配置项说明。
- `dsh_fingerprint_test.go`：8 组用例（最小介入、幂等、容错、不误伤、角色边界、
  品牌规则不回退、开关回退、端到端、多模态 part）。

## 6. 后续观察点

- 上游若调整词组边界：把 `dsh_fingerprint_neutralize` 关掉即可回到旧行为，
  或按新的最小触发块更新正则（先做真实网关消融，勿凭社区结论改）。
- 若 DSH 内核把 `@` 段挪进 `user` 消息，需重新评估（当前上游不扫 user）。
