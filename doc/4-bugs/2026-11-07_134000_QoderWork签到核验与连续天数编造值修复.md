# QoderWork 生产签到核验与「连续天数」编造值修复

- 日期：2026-11-07
- 状态：已核验（链路正常）+ 已修复 3 处缺陷（0.13.2 已发布）
- 来源：用户当轮指令「生产的 qoderwork 的签到是不是有问题？查看一下」
- 影响插件：`qoderwork-provider`（0.13.1 → 0.13.2）

## 1. 核验结论

**签到链路正常，没有漏签。** 两个生产账号的差异来自上游按账号下发活动，不是插件失败。

### 1.1 上游 campaigns 只读探测（2026-11-07 13:40，未执行任何 claim）

| 账号 | showCampaign | 活动条目 | 判定 |
|---|---|---|---|
| `01a1595b…` | true | `CLAIM_BENEFIT + CREDITS 100`，窗口 11-07 10:00 → 11-08 09:59，`claimStatus=CLAIMED`；另有 `VIEW_DETAILS` 订阅推广 | 今天 12:03 已领取成功 |
| `01a15e9a…` | true | 仅 `VIEW_DETAILS` 订阅推广，**无 CLAIM_BENEFIT 条目** | 上游未给该账号下发签到活动 |

### 1.2 调度器在跑的物证

两个 auth 文件 mtime 均为 `2026-11-07 12:03`，等于 12:00 槽位 + `schedulerJitterMax`（0–5 分钟随机抖动）。若调度器未启动，文件不会被写。

### 1.3 面板状态与管理 API 一致

- `01a1595b…`：`active=true, today_checked_in=true, today_credit=100`，积分包 1400 总 / 1199 余
- `01a15e9a…`：`active=false, show_campaign=true, today_checked_in=false` → 面板按钮显示「未下发」并禁用，title 说明「活动由服务端按账号下发」，语义正确

## 2. 取证中暴露的三处真实缺陷

### D1 `streak_days` 是编造值

`fetchCheckinStatus` 在 `todayChecked` 时执行 `sum.StreakDays = 1`。上游 campaigns 响应**没有**连续签到天数字段（campaign 只有 `campaignId / actionType / claimStatus / startAt / endAt / benefit`）。面板据此显示「连续 1 天」，用户会以为昨天断签了。

### D2 签到成功分支不返回 streak

`checkinOneAccount` 的 success 分支只返回 `reward_credits`，没有 `streak_days`。面板 toast：

```js
"+"+gain+" 积分 · 连续 "+(res.streak_days??"?")+" 天"
```

`?? "?"` 退化成 **「连续 ? 天」**——这是用户最容易看到的异常。

### D3 签到零日志

`logCheckinFailure` 只覆盖 campaigns 请求失败。以下路径全部静默：

- 定时路径 status 失败（直接 return）
- 定时路径 claim 失败（`callErr != nil` 无日志）
- 无活动跳过 / 今日已签跳过
- 领取成功（无任何记录）

后果：用户问「签到是不是有问题」时，运维无法从日志区分「没活动」「已签」「失败」。

## 3. 修复（0.13.2）

| 项 | 改动 |
|---|---|
| 去编造 | 移除 `StreakDays = 1`，字段恒 0 表示上游未提供；`checkinSummary` 给 `StreakDays/TotalCredits/WeekCheckinDays/Season` 补注释标明「上游不提供、保留兼容」 |
| 面板文案 | 成功 toast 改为「+N 积分」/「今日签到完成」，不再宣称连续天数；success 与 already 统一口径 |
| 补日志 | 手动路径：`skip already` / `skip no_campaign` / `ok credit=+N` / claim 失败；自动路径：`auto-status` / `auto-claim` 失败、`auto checkin ok`、定时跳过 |

红线未动：领取流程、槽位调度（00/04/08/12/16/20）、活动窗口判定（`startAt`/`endAt`）、`active` 判定语义均不变。

## 5. 边界

- 上游不提供连续天数，本轮选择**不显示**而不是本地推算。若要展示真实连续天数，需插件自己持久化「每日是否签到」的历史（sidecar），属于新功能，本轮不做。
- `total_credits` / `week_checkin_days` / `season` 同为上游未提供字段，面板当前不渲染，保留仅为兼容旧接口。
- 无活动账号（`01a15e9a…`）不会因插件重试而变成可签——活动由上游按账号下发。
