## 6. STYLE-04 结构与落点

- **`creation_watermark.go` 整文件删除而非留空函数**：它的守卫 `if asset.Key == "" || asset.isVideo() || seen[asset.Key] { continue }` 已经把视频全部跳过，删掉图片能力后这个文件里没有任何一行会执行。留着只会让下次读代码的人以为「水印处理还在」。
- **`postBusinessJSON` 一并删除**：删 watermark 后它没有调用者。`businessEndpointOverride` / `swapBusinessEndpoint` 虽然原本服务它，但 `video_chain.go` 的 `postChainJSON` 也在用（同一套 override 机制），因此保留。
- **不新建文件**：本轮是纯删除 + 就地收敛，视频相关的新逻辑在 0.1.26~0.1.29 已全部落到 `video_chain.go` / `creation.go` / `creation_parse.go` / `creation_render.go`，无需新文件。
- **测试文件落点不变**：`creation_test.go` 承接视频解析与渲染用例，`video_chain_test.go` 承接回灌用例，`active_ping_test.go` 承接面板探活用例。`creation_live_test.go` 删掉两个生图端到端函数后只剩两个视频真机用例。
- **`workmode_test.go` → `request_test.go`** 的重命名发生在此前版本，本轮继续沿用该文件名，未再改动。

## 7. STYLE-08 Go 写法

1. **不保留「只为 someday」的空函数**：`isVideo()` 例外，但注释写清了它仍在被两类地址判定使用，属「当下有用」而非「未来可能有用」。
2. **不用 `_ = x` 消除未使用变量**：`runActiveTest` 删掉 `sawProduct` 后直接删声明，没有留 `_ = sawProduct`。哨兵实验里临时用过 `_ = sawResume` 验证，但那只是实验态，已恢复。
3. **删除后同步删除 import**：`creation_render.go` 删 `image_url` 分支后不再需要 `net/http`；`creation_live_test.go` 删两个函数后不再需要 `encoding/json` 与 `pluginapi`。每次删完立即跑 `go build`，避免残留未使用导入。
4. **断言里不用字符串匹配判断 JSON 键是否存在**：`TestBuildConfirmOptionMatchesWebShape` 里判断 `agent_mode` 是否存在时用 `json.Unmarshal` 到 map 再判顶层键——`aggregate_params` 内部仍有同名的空串键，字符串匹配会误报。这个教训从 0.1.27 沿用至今。
5. **哨兵改动前先整份备份**：`active_ping.go` 的哨兵脚本早期用反向 `-replace` 改 `return false`，因为文件里有多处 `return false` 而改错位置。现在一律「整份读入 → 精确替换 → 整份写回」，且替换串必须 `assert count == 1`。
