## STYLE-04 函数签名与参数结构

| 函数 | 签名 | 本轮变化 |
| --- | --- | --- |
| `verifyOf` | `(e *streamError) *verifyDecision` | 新增；方法挂在 `streamError` 上，不新开自由函数，避免多传一个参数 |
| `streamErrorHint` | `(e *streamError) string` | 新增；单参数，与 `statusCodeHint(code, desc)` 的两参数形态区分开——它消费的是整帧而不是两个散值 |
| `statusCodeHint` | `(code int, desc string) string` | 无签名变化，仅文案 |

没有把 `streamErrorHint` 做成 `statusCodeHint` 的第三参数（如 `hint(code, msg, decision)`）：`statusCodeHint` 的调用点里有一半只拿得到 `(code, desc)`，硬加参数会逼所有调用点传空串，属为改一处而污染全局签名。分两个函数、由调用点选，是更小的 diff。

## STYLE-08 语言与框架特异写法

- `Extra` 用内联匿名结构体而不是另立具名类型：它只被 `verifyOf` 读一次，且字段就两个（`decision` / `ack`），立类型属过度设计。这与文件内 `streamError` 本身「只有 2 个字段」的形态一致。
- `decision` 是**嵌套 JSON 字符串**，`verifyOf` 里用 `json.Unmarshal([]byte(raw), &d)` 二次解析；解析失败与 `Type != "verify"` 合并在同一个 `if` 里返回 nil，不写两层嵌套判断。
- `streamErrorHint` 里 `if d := e.verifyOf(); d != nil { ... }` 用了 Go 的 if-初始化语句，避免先声明再判空；`fmt.Sprintf` 只拼一条验证文案，沿用文件内既有的 `fmt.Sprintf("…%s…", …)` 写法。
- `statusCodeHint` 的 `case 710022004, 710022005:` 合并写法保持不变（两码共用一条文案）；新文案是单行字符串字面量，未引入反引号或多行拼接。
