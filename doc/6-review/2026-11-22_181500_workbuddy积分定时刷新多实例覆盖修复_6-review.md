## 7 语言与框架特异写法（STYLE-08）

六条本轮刻意遵守的 Go 写法：

1. **平台差异用 `//go:build` 双文件而非运行时 `runtime.GOOS` 分支**。`processAlive` 的 Unix 实现用 `syscall.Kill(pid, 0)`、Windows 用 `os.FindProcess`，编译期就只保留一支，不存在「跑起来才发现另一个平台的分支编译不过」。
2. **`errors.Is(err, os.ErrNotExist)` 而不是比较字符串**。载入路径区分「文件不存在」（定稿为无数据）与「真实 IO 错误」（保持未载入），rename 重试也只在 `ErrNotExist` 时触发。
3. **锁的作用域收到最小**。`persistCreditSnapshot` 只把「把内存镜像叠加到合并结果」这一段放进 `RLock`（第 3 步），序列化、建目录、写临时文件、rename 全部在锁外——否则整轮落盘会阻塞所有读快照的面板请求。
4. **`defer` 只用于必然执行的清理**。`creditSnapshotMu.RLock` 在叠加段之后立刻 `Unlock`（不是 `defer`），因为后续步骤不再需要锁且失败路径多，`defer` 会把锁持有到函数末尾。
5. **临时文件失败要清理**。`os.Rename` 失败先 `_ = os.Remove(tmp)`，重试分支同样清理——否则每次失败都在 `data/` 里留一个垃圾文件。用例 `TestPersistCreditSnapshotUniqueTempName` 就是盯这条。
6. **无 `else` 嵌套**。`orphanOwnerMarker` 的四个前置判断全部是 `if … { return false }` 提前返回，最后一行 `return !processAlive(pid)`，没有 `if alive { return false } else { return true }`。

一处**没有**做但值得记下的：`ensureCreditSnapshotLoaded` 的失败态没有加最小重试间隔（`deferral:` 注释已标）。失败的频次受面板刷新与扫描周期约束，最坏是每次面板请求重读一次磁盘；真要加窗口需要一个 `lastLoadAttemptAt` 全局，而它本身也要受锁保护，收益在 IO 持续失败时才成立。
