## 3. 本轮代码风格契约（编码前产出，STYLE-09 依据）

| 维度 | 契约 |
|---|---|
| 命名 | 新增符号沿用同域既有前缀：会话域 `session*/maasSession*`，MaaS 协议域 `maas*/newMaas*`，失败分类域 `is*`/`*Marker`，与 `workbuddy` / `traework` 同类插件同构 |
| 结构 | 纯函数优先（会话键派生、头构造、信封构造均可独立单测）；状态放包级变量 + 专用锁，不新增裸全局 |
| 注释 | 中文；函数头写整体说明 + `[参数]` + `[返回]` + `最近修改时间：YYYY-MM-DD；改动原因：…`；常量与字段只写一句话作用 |
| 日志 | 本轮未新增业务日志（会话/票据/头均为内部状态，无可观测诉求）；不打印凭据原值 |
| 错误处理 | 上游错误一律走既有分类入口（`isQueueFrame` / `isAccountFailure` / `shouldRotateOnUpstreamErr`），不新增旁路吞错 |
| 复用 | 低熵会话判定**移植同仓 traework 2026-11-10 的既有实现**（同名同义），不新造第二套；分阶段超时**对齐 workbuddy 2026-11-07 的既有实现**（同常量名同取值） |
| 排版 | gofmt 口径；CRLF 跟随仓库既有 Go 文件；测试文件与被测源码同目录同包（与 qwenwork 既有 30+ 测试文件同址） |
| 禁用写法 | 不为省改动堆特判 flag；不搞双轨分流；不引入新依赖；不批量格式化无关文件 |

## 4. 逐步证据

### STYLE-01 静态格式与编码一致性

- 证据：`python scripts/qwenwork_format_check.py` → 全部改动文件 **UTF-8 无 BOM、无尾随空白、无孤立 CR**；LF 副本上 `gofmt -l` 仅命中 `qwenwork/max_tokens_test.go`。
- 存量判定：`git show HEAD:qwenwork/max_tokens_test.go` 的 LF 副本**同样**被 `gofmt -l` 命中（该文件原有手工对齐的 struct 字段间距），本轮只改了其中两行调用签名，**未顺手格式化无关行**（符合「变更最小化」）。
- 结论：**PASS**。

### STYLE-02 命名与符号引用一致

- 证据：`maasSessionKeyFromPayload` / `maasSessionKeyFromSeed` / `payloadString` / `payloadTextFromContent` / `lowEntropySessionID` / `minSessionEntropyChars` / `modelPoolBusyMarker` / `serviceUnavailableMarker` / `isModelPoolBusyBody` / `maasDeviceType` / `maasUserAgent` / `newMaasRequestID` / `newMaasTraceID` / `newMaasHex` / `storeMaasSessionLocked` / `pruneMaasSessionsLocked` / `maasCacheMaxEntries` / `maasClientRequestSource` —— 全部 camelCase、无同义不同名；`maasSessionKey` 与既有 `sessionKey` 语义显式区分（前者=上游会话，后者=路由会话），命名与注释双处声明。
- 同名符号无跨包冲突（`qwenwork` 独立 `package main`）。
- 结论：**PASS**。

### STYLE-03 注释分层与定义位置

- 证据：本轮新增/改写的函数头均含 `[参数]` / `[返回]` / `最近修改时间：…；改动原因：…`；常量（`maasCacheMaxEntries` / `maasClientRequestSource` / `modelPoolBusyMarker` / `serviceUnavailableMarker` / `minSessionEntropyChars`）只写一句话作用；字段与行内未平铺完整格式；局部变量逐行声明（`attemptStarted := time.Now()`），无 `var (...)` 分组。
- 注释语言：全中文，符合 `comment-rules`。
- 结论：**PASS**。

### STYLE-04 函数签名与参数结构

- 证据：`pumpUpstreamStream` 由 13 参增至 15 参（新增 `maasSessionKey` / `hostCallbackID`），`collectUpstreamStreamOpenAI` / `doExecuteOnceQwenWork` 同理。
- 判定依据（优先级：当前文件稳定写法 > 同目录/同模块写法 > 通用 skill）：本仓 4 个同型插件（`workbuddy` / `traework` / `qoderwork` / `qoder-ai`）的 `pumpUpstreamStream` **一律是 13~15 参的单行签名**，`workbuddy` 0.21.x 的同款 13 参签名已通过同款 6-review。本轮新增的两个参数是**语义必需的会话键拆分与 callback 透传**，不是可选扩展字段；为此改造成结构体会与 4 个兄弟插件的同型函数形态分裂，且把改动面从 1 个插件扩散到 5 个同型函数签名，超出本轮边界。
- 结论：**PASS**（沿用同仓同型函数的既有签名形态，记录为已知偏离项，不做跨插件统一改造）。

### STYLE-05 结构与落点

- 证据：会话身份派生落在 `qwenwork/session_auth.go`（会话域）；MaaS 票据/出站头/缓存淘汰落在 `qwenwork/maas.go`（MaaS 协议域）；失败分类落在 `qwenwork/policy.go` + `qwenwork/accountFailover.go`（与既有 `isQueueFrame` / `shouldRotateOnUpstreamErr` 同址）；宿主桥落在 `qwenwork/host_bridge.go`（与 `workbuddy/host_bridge.go` 同构）；测试文件与被测源码同目录同包；辅助脚本落在仓库既有 `scripts/`。
- 无新增目录、无跨域依赖、无实体/工具层错置。
- 结论：**PASS**。

### STYLE-08 Go 语言特异写法

- 证据：常量均为显式值、无 `iota`；`strings.TrimSpace` 只用于会话标识归一化与上游报文裁剪这类**确有脏空格风险**的位置，未对 `item.ID` 类字段乱加；局部变量逐行声明；函数签名单行；`sort.Slice` 用于票据淘汰排序。
- 结论：**PASS**。

### STYLE-09 测试资产与编码前契约

- 证据：测试资产落 `qwenwork/` 同目录同包（与该插件既有 30+ 个 `*_test.go` 同址，`cgo-shim-build.py` 的 `go test ./...` 直接覆盖）——本仓 Go 插件的白盒测试沿用同包形态（`workbuddy` / `traework` / `qoderwork` 同款），根 `test/` 目录承载的是跨语言黑盒脚本，本轮无此类脚本。
- 编码前契约：见第 3 节，已在写码前产出并逐项落地。
- 测试资产归位：新增 5 个测试文件均在 `qwenwork/`，无测试资产落进 `doc/`；`doc/5-tests/` 只承载说明与证据。
- 结论：**PASS**。
