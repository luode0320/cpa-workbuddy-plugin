## 7 语言与框架特异写法（STYLE-08）

八条本轮刻意遵守的 Go 写法：

1. **不持有跨调用状态的指针**。`acquireUpstream` 在临界区内只读写 `upstreamGates` 里的 `*accountGate`，返回值 `upstreamTicket` 是值拷贝（`authID` + `kind`），调用方拿不到 gate 本身，也就不可能绕过锁改 `inflight`。
2. **`close` + 换新 channel 做广播**，而不是 `sync.Cond`。`releaseUpstream` 里 `close(upstreamGateChanged); upstreamGateChanged = make(chan struct{})`——`sync.Cond` 需要一个总在锁内的等待循环，而这里等待者要同时等 `ctx.Done()`，`select` 更好写。
3. **归还只走一个 defer**。`streamCompletion` 用 `var gateErr error` + `defer func() { releaseUpstream(ticket, gateErr) }()`，而不是先释放再置标记（第一版是后者，用户指出多余后改掉）。`gateErr` 的命名表明它是「给闸门看的错误」，不是「本函数的错误」。
4. **流内错误单独探测**。`scanSSE` 的流内 `STREAM_ERROR` 不上浮到返回值，所以加 `wrapStreamErrorProbe` 旁听——没有为了这个改 `scanSSE` 的签名（那会影响 15 处调用点）。
5. **错误类型比字符串可靠**。`postChainJSON` 的非 200 从 `fmt.Errorf` 改成 `*upstreamError`，否则 `classifyUpstreamError` 拿不到 `StatusCode`/`Code`，闸门与 failover 都会失明。`err` 包装链没有用 `%w` 包 `*upstreamError` 再断言——直接返回原值，避免下游 `errors.As` 与 `classifyUpstreamError` 两套识别逻辑分叉。
6. **`time.Timer` 用完 `Stop`**。`waitUpstreamGate` 的 `wait > 0` 分支用 `time.NewTimer` + `defer timer.Stop()`，不用 `time.After`（后者在提前返回时会留一个无法回收的 timer）。
7. **测试可替换的入口用 `var` 而非参数**。`retrySleep` 是 `var retrySleep = func(d time.Duration) {...}`，用例里直接换掉——比在每个调用点加函数参数干净，也与同仓库 `swapCompletionEndpoint` / `swapVideoPollTiming` 的既有手法一致。
8. **无 `else` 嵌套**。`claimActiveTest` 的 `if state.busy && now.Sub(state.lastAt) < activeTestCooldown { return ..., false }` 之后直接 `return 0, true`，没有 `if !busy { return true } else { return false }`。

一处**没有**做但值得记下的：`upstreamGates` 用 `map[string]*accountGate` 且从不清理。账号被删除后 gate 会一直留在内存里。单个 gate 是三个字段（int + 两个 time.Time），一千个账号也就几十 KB，属可接受的 deferral；真要清理需要在删账号路径上挂钩子，而 `deleteAuth` 与 `disableAuth` 有多条入口（面板、文件监听、宿主 RPC），漏一处就漏一处，风险大于收益。
