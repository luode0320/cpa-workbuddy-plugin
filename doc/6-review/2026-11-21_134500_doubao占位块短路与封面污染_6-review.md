## 4 STYLE-03 注释分层与定义位置

- **判据的理由写在定义处**：`playable` 的函数头解释「为什么不能只看 `len(assets) > 0`」——上游会把生成中的占位块推进来，那种块有 id、有状态、甚至带封面，但 URL 是空的。`hasPlayableAsset` 只写一句「替代裸的 `len(assets)` 判据」，不复述 `playable` 的理由。
- **函数头保留项目既有元信息格式**（`[参数]` / `[返回]` / `最近修改时间` + 改动原因）：`playable`、`hasPlayableAsset`、`assetFromVideo`、`attachAssets`、`mediaExtension`、`describeAssets`、`streamAssetFrames`、`bestStream`、`ensureVideoAsset`、`videoAssetAmong`、`streamIDOf` 十一个函数全部带齐。
- **行为变更的理由写在被改的那一行旁边**，不堆在函数头：
  - `SSE_ACK` 分支：「逐字段非空才覆盖：确认轮带着 section_id 进来，上游 ACK 里这个字段可能为空，无条件赋值会把有效的续接点抹成空串，客户端下一次续接就断了（`attachResumePoint` 遇到空串会整条省略）」。
  - `bestStream`：「同分时再按 key 定序，把「随机」压成「固定」」。
  - `executorExecuteStream`：「只解一次：`decodeExecutorRequest` 已经把同一份 raw 解进 `pluginapi.ExecutorRequest`，这里再解一遍只为拿 `stream_id`，等于把整个请求体（含 `StorageJSON`）解析两次」。
  - `streamIDOf`：「`stream_id` 不在 `pluginapi.ExecutorRequest` 里（那是插件自己的信封字段）」。
- **删除也要说明**：`creation_parse.go` 的 `assetFromVideo` 函数头写明「封面图不是成品，它是一张 JPEG，塞进 URL 会让 media 里出现 `{"type":"video","url":"...jpg"}` 这种自相矛盾的条目，客户端按视频去播放只会失败」；收尾处补「占位帧也要交出去：回灌层靠「有没有出现过创作块」判断上游是否真的开跑，丢掉占位块会让它以为上游没启动，直接误报「上游没有开始渲染」」。这两句是「为什么删」和「为什么不能连带删干净」的完整交代。

## 6 STYLE-05 结构与落点

- `playable` / `hasPlayableAsset` 放在 `creation.go` 的 `isVideo()` **紧后面**：三个都是 `creationAsset` 的「这个资产是什么」判据，连在一起读一次就够，不用翻文件。
- `firstChoiceMessage` 放在 `creation_render.go` 的 `attachAssets` **之前**：调用方在被调用方上方，与文件里既有的「小工具在前、主流程在后」顺序一致。
- `streamIDOf` 放在 `executor_stream.go` 的 `collectStreamResponse` **之前**：它是流式入口的一个小解析步骤，紧贴第一个使用者。
- 配置项与常量层未新增任何符号（本轮不涉及超时）。

## 7 STYLE-08 Go 写法

1. **`playable()` 用 `strings.TrimSpace(a.URL) != ""`** 而不是 `a.URL != ""`：上游可能给纯空白地址，与 `assetFromVideo` 里既有的 `strings.TrimSpace(asset.URL) == ""` 保持同一判据。
2. **`hasPlayableAsset` 用早返回**（命中即 `return true`），不在循环里攒布尔；末尾 `return false` 兜底，与 `videoAssetAmong` 的写法同族。
3. **`firstChoiceMessage` 用 `type switch`** 而不是两次类型断言：`case []map[string]any:` / `case []any:` / `default: return nil, false`，三种分支在同一个 `switch` 里横向可读，也比 `如果 A 失败再试 B` 少一层缩进。
4. **`bestStream` 的定序用 `sort.Strings(keys)`**，没有换成有序切片或 `slices.Sort`：既有文件已 `import "sort"` 之外的场景没有 `slices` 依赖，引入新导入只为一个 `Sort` 不划算。
5. **`streamIDOf` 的 raw 解析用最小匿名结构体** `var probe struct { StreamID string \`json:"stream_id"\` }`，不复用 `executorStreamRequest`（那个嵌了 `pluginapi.ExecutorRequest`，等于把整份请求再解一次，正是本轮要消除的浪费）。
6. **`describeAssets` 的早返回从开头挪到末尾**：原实现 `len(assets) == 0` 直接返回，现在要按 `playable()` 过滤，只能先攒 `parts` 再判空，否则「有资产但全是占位」时会返回「已生成视频」。
