## 7 语言与框架特异写法（STYLE-08）

1. **反射读 `yaml` 标签而不是硬编码字段名**：`reflect.TypeOf(Config{})` + `cfgType.Field(i).Tag.Get("yaml")`。硬编码字段列表的测试只能防住「删了某条声明」，防不住「新增了 Config 字段但忘了声明」——那恰恰是本轮要防的回归。
2. **跳过空标签与 `-`**：`if key == "" || key == "-" { continue }`，与 `configurePlugin` 里对 yaml 标签的使用口径一致。
3. **`pluginapi.ConfigFieldTypeBoolean` 单独断言**：类型错误的后果是管理端把开关渲染成文本框，与「漏声明」是不同的失败模式，各自给一条明确报错文案。
4. **`declared` 用 `map[string]pluginapi.ConfigFieldType` 而不是 `map[string]bool`**：顺便验证类型，少一次遍历。
5. **空名与空描述也拦**：`field.Name == ""` / `field.Description == ""` 直接 `t.Fatal`，避免声明一条空壳。
6. **不用 `t.Run` 拆子测试**：这个用例的断言是线性的「先建表 → 再逐个核对」，拆子测试反而要共享 `declared`，与同文件既有用例的扁平风格不一致。
