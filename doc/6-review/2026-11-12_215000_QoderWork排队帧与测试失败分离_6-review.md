### STYLE-08 语言与框架特异写法（owner: golang-patterns、frontend-ui-visual-rules）

Go 侧：
- `json.NewDecoder(strings.NewReader(...))` 而非 `json.Unmarshal` —— 因为错误文本形如 `upstream 200: 403: 10605: {...}`，前缀无法整体 Unmarshal 且尾部可能有残留；Decoder 允许尾随内容，是本场景的正确工具（不是绕路写法）。
- 扫描起点用 `for i := 0; i < len(body); i++ { if body[i] != '{' { continue } ... }` 的**字节遍历**而非正则：body 是上游报错原文，正则要处理换行/引号转义，字节扫描更短也更难写错。
- `errors.As(err, &queueErr)` 而非类型断言 `err.(*queueFrameError)`：`sendActivePingQoder` 会在多处返回该类型，上一层可能被 `fmt.Errorf("...: %w")` 包过，`errors.As` 才能穿透（未来加包装也不会静默失效）。
- `truncateRedacted` 先脱敏再截断的既有口径被沿用，未新写截断 helper。

前端侧：
- `.r-warn` 用 `word-break:break-word`，与兄弟规则 `.r-err` 的 `break-all` **有意不同**：`.r-err` 展示的是无空格的截断 JSON，必须 `break-all` 才能不溢出；`.r-warn` 展示的是中文散文（「上游排队中 (模型: X，队列 p4)，约 60 秒后可重试」），`break-all` 会把词从中间劈开，`break-word` 才可读。共用 `--warn` 变量与本文件既有 `.toast.warn`（panel.html:122）口径。
- 三态取值集中在四个 `const`（`queued` / `ok` / `kind` / `head` / `text`），模板串只做插值，避免在 `innerHTML` 里堆嵌套三元；`esc()` 覆盖 `model` 与正文两处插值，无 XSS 回归。
- 未新增任何网络请求或轮询：排队提示给了「约 N 秒后可重试」，但不自动重试 —— 上游 110 日调用上限是既知成本，自动重试会把面板点一次变成暗中多打。
