## STYLE-03 注释

- 三个新增函数都写全了 `[参数]` / `[返回]` / `最近修改时间 + 改动原因` 三段，与包内既有函数注释完全同构。
- `resolveAuthFilePath` 的函数注释把**故障史**写进了注释：「旧实现让调用方直接传 `sa.PhysicalPath`，而 `saveCredentials` 从不回填该字段，导致追加写入 ms_token 时路径为空、被安全闸门拒绝（2026-11-15 生产日志：『不安全的凭据文件路径：』后为空）」。这不是复述代码，而是记录为什么不能退回旧写法。
- `writeAuthFileDirect` 体内按项目规范补了三段步骤编号注释：`// 1.` 路径解析必须在锁外完成、`// 2.` 只在真正写盘期间持锁、`// 3.` 宿主尚未接管该凭据时先注册。其中第 1 段把**自锁成因**写清楚了（「解析过程会走宿主 RPC 与 getAccountsDir，后者自己拿 authFilesMu 读锁，而本函数随后要拿写锁——RWMutex 不可重入」）。
- `login.go` 的 msToken 分支补了 `else` 注释解释「为什么缺失也要打日志」：0.1.16 之前拖入的书签不会采集它，用户只会在面板看到「未采集」却不知道为什么。
- `checkin.go` 的 `case 2:` 用块注释记录了实测报文与推断链（`{"data":null,"code":2,"message":"campaign not found"}` + 同刻同 `campaign_group_code` 对被投放账号正常），并说明「写成『已下线』会把用户引向等待平台恢复，而实际永远等不到，正确动作是换号」。
- 两个测试文件的断言口径变更都补了变更依据注释，而不是直接改期望值。

## STYLE-08 语言与框架特异写法

- `sync.RWMutex` 不可重入这一点本轮踩实并写进了注释：路径解析全部搬到锁外，写盘收敛到 `writeCredentialFile` 内独占锁。这是 Go 并发正确性问题，不是风格偏好，但纠正方式（缩临界区而非换锁类型）符合项目既有加锁口径。
- `json.MarshalIndent(auth, "", "  ")` 保持两空格缩进，与落盘文件既有形态一致；`os.WriteFile(tmpFile, data, 0600)` 保持 0600 权限；`os.Rename` 原子替换——三者都与旧实现逐字一致，未改。
- 宿主 RPC 请求体的构造方式与 `listHostAuthFiles` 完全相同（`json.Marshal(map[string]string{"auth_index": entry.AuthIndex})`），没有为「新」函数另造一套。
- 条件写法的取舍：`if !hadPhysicalPath && !auth.Disabled { if errSave := ...; errSave == nil { if hostPath := ...; hostPath != "" { ... } } }` 用了三层嵌套而非提前 return，因为提前 return 会跳过后面的 `auth.PhysicalPath = targetPath` 兜底赋值；这种「嵌套换正确性」的写法与包内 `listHostAuthFiles` 的多层 `if ... continue` 风格一致。
