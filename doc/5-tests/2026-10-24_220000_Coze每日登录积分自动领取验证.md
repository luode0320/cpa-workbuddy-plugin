## 2. 上游契约实测证据

### 2.1 对照实验（每个账号只打一个端点，60 秒后观察）

| 账号 | 动作 | 触发前 today | 触发后 today |
|---|---|---|---|
| 75c744 | `coze_space/activity/info` | 无 | 无 |
| a2d9fc | `commerce/get_user_benefit` | 无 | 无 |
| b161bd | **`credit/balance/check?account_type=2`** | 无 | **1500** |
| b3f25e | `incentive/user_task/list` | 无 | 无 |
| ff6ae4 | 不请求（对照） | 无 | 无 |

### 2.4 幂等

同一账号连打 check 三次，明细中当日「每日登录」条目始终 1 条、总额 1500。

### 2.5 pass 语义全账号复核（推翻初版假设）

全 9 个账号各打一次 check，随后查 remain 与今日「每日登录」条目数：

| 账号 | check 响应 | remain | 今日条目 |
|---|---|---|---|
| 1185dd | `pass:true` | 1500 | 1 |
| 2a143e | `pass:true` | 1500 | 1 |
| 75c744 | `pass:true` | 1500 | 1 |
| a2d9fc | `pass:true` | 1500 | 1 |
| b161bd | `pass:true` | 1500 | 1 |
| **b3f25e** | **`pass:false, deny_reason:1`** | **1500** | **1** |
| d74585 | `pass:true` | 1500 | 1 |
| **f18297** | **`pass:false, deny_reason:1`** | **1500** | **1** |
| ff6ae4 | `pass:true` | 1500 | 1 |

**结论：`pass` 描述余额是否够用，与发放无关**（pass=false 照样到账 1500）。
初版按 pass 判定为错误的实现，已改为「明细确认」，并以
`TestConfirmDailyCredit_MarksClaimedWhenTodayItemHasBalance`（桩返回 pass=false）
锁定该语义。

### 2.6 display_status 取值

| 值 | 含义 |
|---|---|
| 2 | 当天可用（即将过期） |
| 3 | 未来到期 |
| 4 | 已过期 |

## 4. 变异反证

| 变异 | 预期失败用例 | 实际 |
|---|---|---|
| 把 `claim` 移到 `fetch` 之后 | 顺序用例 | **KILLED**：`调用序列应为 [claim fetch confirm]...` |
| 跨日判定退化为「领过就算今天」 | 跨日用例 | **KILLED**：`昨天的领取不应算作今天已领` |
| 确认时要求 `passHint` 为真 | `pass=false` 到账用例 | **KILLED**：`明细里当天有余额条目时必须判定为已领取` |
| 请求失败时仍据明细确认 | 失败确认用例 | **KILLED**：`请求失败时不应据明细标记为已领取` |
| 确认时忽略 `remaining>0` | 零余额用例 | **KILLED**：`余额为 0 的条目不应判定为今日已领` |

五项均精准 FAIL，还原后全绿。

## 5. 未覆盖项

- **生产端到端**：本轮验证时插件尚未发布部署，`/claim-daily` 与面板
  「领今日积分」按钮未在生产实际点击过，属发布后待验项。
- **面板 UI 点击**：本地无 CPA 实例，只做了脚本语法校验，未做浏览器交互验证。
- **`deny_reason` 其它取值**：实测只观测到 `1`，其它取值语义未知。
  由于该字段已确认与发放无关，代码不再据它判定任何行为，只记录 `pass` 作排查线索。
