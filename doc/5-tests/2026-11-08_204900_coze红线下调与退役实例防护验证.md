## 5. 生产事故根因与处置

### 5.1 事故形态

18:55:53 coze 0.7.5 热重载（`hot reloaded active_version=0.7.5 retired_version=0.7.4`）。
19:02:52-55 有一轮巡检把 23 个账号整批写盘禁用，
**写盘内容 `low_credit_disable_below=200`** —— 该常量只存在于 0.7.4 二进制（新版本是 10）。
19:02:55-19:02:58 连续 4 个 `503 chat/completions`。

### 5.2 根因

宿主 `internal/pluginhost/host.go` 的 `retireLoadedPluginLocked` 只把旧实例放进 `retired` map，
**不调用 `shutdownPluginClient`**（后者仅在 Unload `host.go:568` 与 ShutdownAll 时触发）。
旧实例的巡检 goroutine 因此继续存活，用编译期的旧阈值写盘。

### 5.3 处置（按项目 skill `project-cpa-workbuddy-plugin-account-data-recovery-rules`）

| 步骤 | 动作 | 证据 |
|---|---|---|
| 还原点 | `/root/coze-redline-recovery-20261108_194107`、`/root/coze-zombie-recovery-20261108_195912`、`/root/coze-db-backfill-20261108_203130`（各含 spool 快照 + auth_store 全表 dump） | 三处目录均在生产 |
| 清僵尸 | `DELETE /v0/management/plugins/coze-provider` → 宿主日志 `plugin unloaded` 对 0.7.4 与 0.7.5 **各一条**（19:59:28） | 触发 `shutdownPluginClient` |
| 重装 | `POST plugin-store/coze-provider/install?version=0.7.5` → `registered/enabled/effective_enabled` 全 true | |
| 修 DB | 15 个非人工禁用账号 `UPDATE auth_store SET content='<JSON 字面量>'` | 8 个人工禁用**未动** |
| 清标记 | spool 里 7 个 `low_credit_disable=true, below=200` 残留标记清零 | 归属标记只属低额机制 |

**踩坑（已写入项目记忆）**：`CAST(X'<hex>' AS JSON)` 会把 JSON 列二次编码成 `"base64:type15:..."` 字符串，
`JSON_EXTRACT` 对其返回 NULL；必须直接写 JSON 字面量。另：MySQL `--raw` 输出 JSON 列是二进制形态、
**不带 `--raw` 才是可读文本**，排查时容易被 `base64:type15:` 误导成加密。

**另一个坑**：宿主 `PATCH /v0/management/auth-files/status` 只改内存态与 spool 文件、**不回写 DB**
（DB `updated_at` 停在 11-06）；MySQL 存储模式下必须显式 UPDATE `auth_store`。

## 8. 未覆盖与遗留

- **未做真实浏览器点击**：面板签到徽标改为动态展示后只做了 `node --check` 语法校验与后端字段确认（`daily_credit.amount=60` 已正确下发）。
- **darwin/arm64 平台缺件**：两次 CI 中该平台 job 均被取消（macOS runner 池排队），registry 已移除该平台槽位，Apple Silicon 需后续补发。
- **红线 10 的业务适配性未做长时间观察**：本轮只验证「阈值已生效、误禁已消除、防护已生效」。10 分是否留出足够缓冲需看生产 `sweep.failed` 与禁用频次再定。
- **僵尸实例的 `/proc/1/maps` 仍能同时看到多个 coze .so**：Go 动态库被 `dlclose` 后不真正 unmap，这是正常现象；判定僵尸的依据是「宿主是否调用过它的 shutdown」与「它是否还在写盘」，不是 maps。
