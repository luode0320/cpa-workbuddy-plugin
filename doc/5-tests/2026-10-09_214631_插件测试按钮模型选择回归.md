# 插件测试按钮模型选择回归（本地 shim + vm 验证）

结论：workbuddy / workbuddy-ai / traework 三个插件的「测试」按钮由「随机模型直接测」改为「弹出模型小窗口、点选指定模型再测」后，已完成本地真实执行验证：三插件 cgo-shim build/vet/test 全绿、指定模型单测断言通过、三面板 vm 回归全绿（含旧版反证）；影响：三插件面板测试交互与各自 /test-active 接口；范围：三插件 models.go / active_ping.go / management.go、三插件 *_test.go、三面板 panel.html 与三个回归脚本；非范围：随机定时活跃探测（watchdog）、宿主 ABI、CN 签到与保号链路、cursor/ 与 qoderwork/ 插件；变化：新增只读 /models 路由与 /test-active 可选 model 字段，面板新增测试弹窗；完成标准：shim 全绿 + 哨兵确证 + vm 回归全绿 + 旧版反证失败；术语说明：cgo-shim 是在无 C 工具链的 Windows 上以 CGO_ENABLED=0 复现插件 build/vet/test 的本地脚本，vm 是 Node 内置隔离执行环境，DOM 桩是脚本内构造的最小页面对象；验证状态：本轮真实执行验证已通过，等待风格回归。

## 验证策略

后端逻辑经 go test 白盒单测覆盖；面板 JS 经 go:embed 编入插件 .so，`node --check` 只能查语法、抓不到运行期未定义标识符，故面板按三件套执行：vm 全量执行（抓 ReferenceError / TypeError）、定义与使用成对 grep（抓删除后残留引用）、关键表达式分支断言（抓语法合法的残行），并对 HEAD 旧版面板做反证以证明断言集真实敏感。
