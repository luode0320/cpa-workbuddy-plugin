# 2026-11-29_025000 GLM 每日积分机制与 access_token 缺失根因

## 一、两个提问

1. 「GLM 无签到端点，但是好像每日也可以领积分，是自动发放的吗？」
2. 「glm 的账户好像只有 refresh_token，但是我们看到不是还有 chatglm_token，这是正常使用的 token，为什么我们没有这个。」

## 二、问题一：每日积分是自动发放的

### 2.1 结论

**是的，全自动，没有签到接口可调。** 上游 `score_rule` 字段直接写明：

```
left_score      : 399.01
score_rule      : 免费用户，登录赠送200积分/天
token_left_percent  : 100%
token_usage_percent : 0%
```

### 2.2 证据链

| 时间 | `left_score` | 说明 |
|---|---|---|
| 2026-11-29 02:10 | 199.01 | 0.2.13 联调时读到 |
| 2026-11-29 02:44 | 399.01 | 正好 +200，且期间**没有任何签到调用** |

两次读数之间插件只做过「刷新模型目录 / 读积分」这类只读操作，未调用任何写入端点，积分仍自增 200 —— 说明发放由服务端按登录/活跃状态自动完成。

### 2.3 签到端点探测：全部 404

### 2.4 `user/info` 全字段核对

`GET /chatglm/user-api/user/info` 的 `result` 只有 17 个顶层键：

```
_id, app_channel, avatar, block_info, created_at, idcard_verified, ip,
is_guest, member_info, nickname, phone, phone_code, profile, setting,
sl, sub_account, username, verification
```

- `member_info` 是积分与额度的唯一来源（`left_score` / `score_rule` / `token_left_percent` / `token_usage_percent` / `member_status` / `non_member_number`）。
- `setting` 只有 `sync_storage` 与 `stat_disallowed`，无签到相关。
- `profile` 只有昵称/头像/手机/性别/年龄/职业。
- **没有任何 `sign` / `checkin` / `task` / `reward` 字段。**

### 2.5 对插件的结论

面板不需要「签到」按钮 —— GLM 侧没有可触发的动作，加了就是空按钮。workbuddy 的「全部签到」无法平移，理由成立。

真正有价值的是把 `score_rule` 展示出来，让用户知道「200 积分/天是自动的」。0.2.14 已把 `score_rule` 挂在进度条 meta 的 `title` 上。

## 三、问题二：access_token 缺失是缺陷，已修

### 3.1 现象

导出的 `glm-accounts.json`：

```json
[{
  "type": "glm-provider",
  "auth_id": "glm-766824ea9841d0db",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "label": "glm Ji4HOg",
  "disabled": false,
  "test_failed": false,
  "created_at": "2026-11-28T23:11:32+08:00",
  "updated_at": "2026-11-28T23:11:32+08:00"
}]
```

没有 `access_token`，也没有 `expires_at`。

### 3.2 根因

`StoredAuth` 结构体其实**定义了**这两个字段：

```go
AccessToken string `json:"access_token,omitempty"`
ExpiresAt   int64  `json:"expires_at,omitempty"`
```

但 `acquireToken` 刷新成功后只写内存缓存，**从不回写账号对象**：

```go
result, err := requestToken(refreshToken, cfg)
if err == nil {
    globalTokenCache.mu.Lock()
    globalTokenCache.entries[refreshToken] = result   // 只写内存
    globalTokenCache.mu.Unlock()
}
// 没有 persist 调用
```

`writeAuthFileDirect` 虽然会通过 `mergeStoredAuthIntoDoc` 把 `access_token` 合进 JSON，但从来没人给它赋过值。加上 `omitempty`，空值直接不进文件 —— 于是磁盘上永远只有 `refresh_token`。

这不是「GLM 只有 refresh_token」，是**我们从来没把 access_token 存下来**。

### 3.3 修复

**回写**（`token.go`）：

```go
func persistAccessToken(refreshToken string, result *tokenResult) {
    sa := findAuthByRefreshToken(refreshToken)
    if sa == nil { return }
    sa.AccessToken = result.AccessToken
    if !result.RefreshTime.IsZero() { sa.ExpiresAt = result.RefreshTime.Unix() }
    if result.RefreshToken != "" { sa.RefreshToken = result.RefreshToken }
    sa.UpdatedAt = time.Now().Format(time.RFC3339)
    if err := writeAuthFileDirect(sa.PhysicalPath, sa); err != nil {
        log.Printf("[glm] persist access_token for %s failed: %v", sa.AuthID, err)
    }
}
```

在 `acquireToken` 的刷新成功分支调用。回写失败只记日志，不阻断调用 —— 令牌已在内存缓存可用，不应因为落盘失败让请求挂掉。

**反查**（`authfile.go`）：

刷新发生在推理路径上，此时手上只有 `refresh_token`，需要 `findAuthByRefreshToken` 反查账号才能定位文件。该函数对空串/空白串返回 nil，不做模糊匹配。

**导出补齐**（`management.go`）：

`handleMgmtExport` 导出前遍历账号，对缺 `access_token` 或已过期的补刷一次（未过期沿用），保证导出文件是完整令牌对。这样即便用户从没发过请求，导出的也是可用的。

### 3.4 回写后导出长这样

```json
[{
  "auth_id": "glm-766824ea9841d0db",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
```

## 五、附带发现：并行会话改了模型目录

发布过程中发现 `models.go` 已被另一个会话重写为「2 模型 × 4 模式」结构：

- `modelCatalog` 只有两项：`GLM-5.3`（`if_plus_model=true`）与 `GLM-5.3 Flash`（`if_plus_model=false`）。
- `chatModeCatalog` 是正交维度：标准 / 思考 / 智能体 / 深度研究。
- `resolveUpstreamTarget` 返回三元组 `(assistant_id, chat_mode, if_plus_model)`。
- `allModelEntries` 把两者笛卡尔展开成 8 个模型名。

该改动与本轮 access_token 修复不冲突，已一并提交。注意 `if_plus_model` 的语义在此版本被重新认定为**模型维度**（此前 0.2.11 的结论是「对响应形态无影响」），两者差异在于：0.2.11 只比较了响应帧类型，未比较网页菜单的实际语义。后续若要复核，应以网页菜单两项（GLM-5.3 / GLM-5.3 Flash）为准。

## 六、结论

1. **每日 200 积分全自动发放**，无签到接口（26 条候选路径全 404），`score_rule` 字段自述规则。面板不设签到按钮是正确的。
2. **access_token 缺失是我们自己的缺陷**，已修：刷新后回写、导出前补齐、失败不阻断。此前「只有 refresh_token」不是 GLM 的限制。

四层版本一致：代码 = `VERSION` = registry = 生产 `0.2.15`。
