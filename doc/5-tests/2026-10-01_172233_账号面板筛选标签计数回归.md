# 账号面板筛选标签计数回归（workbuddy / traework / qoderwork）

结论：缺陷已复现、修复并回归通过。三条插件面板的筛选标签计数（全部 / 可用 / 耗尽 / 失败 / 测试）过去只在首屏 `load()` 里算一次，后台刷新把真实积分回填进账号对象后只重画汇总卡，标签长期停在首屏旧值，出现「标签说 51 可用 / 汇总说 21 账号 20 可用」的自相矛盾。修复把标签计数挂到统一渲染入口 `renderSummary()`，并让 WorkBuddy 的「耗尽」判定与后端 `isCreditsExhausted` 同口径。回归脚本对修复前的 HEAD 版本判 FAIL、对修复后的工作树判 PASS，证明用例能真实拦截该缺陷。

## 文档信息

- 来源：用户截图红框指出 WorkBuddy 账号面板「可用 51 / 耗尽 0」与汇总卡「21 个账号 · 可用 20」矛盾；转 Bug 主文档 `doc/4-bugs/2026-10-01_165945_账号面板筛选标签计数未随积分回填重算.md`。
- 实施记录：`workbuddy/panel.html`、`traework/panel.html`、`qoderwork/panel.html` 三个面板插件的筛选标签计数刷新挂点与耗尽判定统一。
- 真实验证：`node test/workbuddy/panel_filter_counts_repro.mjs <plugin>` 在 Node `vm` + DOM 桩里真实执行面板内联 JS，自带断言与退出码。
- 性能验证：N/A，原因为本次改动是面板内纯派生的计数刷新，不涉及耗时链路、并发或数据量变化。
- 图片资产链接：N/A，原因为缺陷证据是面板数值一致性，用脚本断言即可锁死；截图本身只作现象记录，随用户消息提供，未作为回归判据。

## 验证策略

面板的 JS 通过 `//go:embed panel.html` 编进各插件 `.so`，`node --check` 只能查语法、抓不到运行期的标识符或引用错误，也抓不到「计数没重算」这类静默逻辑缺陷。因此本轮统一用 Node `vm` 建隔离上下文 + DOM 桩，把面板内联脚本真实跑起来，再按真实链路驱动：

1. 冷缓存：模拟首屏 `GET /accounts`（后端 `buildDashboardEx(false,false)` 只读缓存），此刻所有账号 `credits=null`。
2. 积分回填：模拟后台刷新把真实 `credits` 逐个回填进 `lastAccounts`，随后用户点击「可用」标签触发一次重绘（= 用户截图那一刻）。
3. 断言：标签计数必须与汇总卡、与同口径筛选结果三者自洽。

夹具固定为 51 个账号 = 30 耗尽 + 1 积分未知 + 20 可用，与用户截图规模一致。积分未知的账号用于验证「没有积分数据不算耗尽」这条边界。

## 测试说明
