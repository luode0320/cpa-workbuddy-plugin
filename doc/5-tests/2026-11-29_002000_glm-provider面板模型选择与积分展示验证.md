# 2026-11-29_002000 glm-provider 面板测试选模型与积分展示验证

## 一、需求

用户在面板截图后提出两点：

1. **测试没有选择模型**，「可以参考 workbuddy」——即点「测试」时应能指定用哪个模型探测。
2. **账户没有显示积分**，「面板也可以参考 workbuddy」。

## 二、workbuddy 的参考做法

| 能力 | workbuddy 的做法 |
|---|---|
| 探活模型 | `pickRandomWorkbuddyModels(sa, limit)` 从候选目录选模型，`sendActivePingWorkbuddy(sa, chosenModel)` 带模型发探活 |
| 积分 | `fetchUserResource(sa)` 调自身 billing API `/v2/billing/meter/get-user-resource`，聚合 `creditsSummary`；面板按账号懒加载 |

workbuddy 的积分走它自己的计费网关，GLM 没有同一套，必须另找上游端点，因此第 2 点不能照搬，只能照搬「面板形态 + 懒加载」。

## 三、GLM 积分端点取证

用真实 `access_token` 对 16 个候选路径做 GET 探测，只有一条命中：

```
200  /chatglm/user-api/user/info
404  /user/credit、/user/quota、/user/point、/user/vip、/user/member、
     /user/resource、/user/balance、/user/wallet、/user/usage、/user/subscribe、
     /user/order、/credit/get、以及 backend-api 下的同类路径
```

命中端点返回的 `result.member_info` 即积分数据：

```json
{"member_status":1,"token_usage_percent":"1%","token_left_percent":"99%",
 "left_score":"199.01","score_rule":"免费用户，登录赠送200积分/天"}
```

由此确定：**积分 = `result.member_info.left_score`，额度用 `token_left_percent` / `token_usage_percent`**。

## 四、实现

### 4.1 新增 `glm/credits.go`

- `creditSummary`：`left_score`、`token_left_percent`、`token_usage_percent`、`member_status`、`score_rule`、`fetched_at`。
- `fetchCredits(accessToken, cfg)`：GET `cfg.UserInfoEndpoint`，复用 `refreshHeaders` 的伪装头并把 `X-Device-Id` 取自令牌载荷（与 0.2.7/0.2.8 同源约束），`Accept` 覆盖为 `application/json`。
- `handleMgmtCredits(query)`：按 `auth_id` 找账号 → `acquireToken` → 拉积分 → 返回 `{"ok":true,"credits":{...}}`。

`Config` 新增 `user_info_endpoint` 可覆盖端点；`userInfoEndpoint` 常量此前已定义但从未被引用，本次接入而非新建常量。

### 4.2 面板

- 账号卡片新增「积分」行，占位 `读取中…`，由 `loadCredits(id, el)` 懒加载后写入 `199.01 分 · 余量 99%`，`title` 挂 `score_rule`。
- 账号卡片新增模型下拉 `.modelsel`，选项来自 `/models`（五个别名），随「测试」一起提交。
- `testAccount` 读取同卡片下拉值，非空时作为 `model` 提交；后端 `handleMgmtTest` 原本就支持该字段，缺省仍用第一个模型。
- `renderGrid` 渲染后逐张触发积分加载，账号多时不阻塞首屏。
- 新增 `.modelsel` 样式，沿用既有 CSS 变量。

## 五、中途修复：`/credits` 取不到 `auth_id`

0.2.9 部署后 `/credits?auth_id=...` 恒返回 `{"error":"auth_id required"}`。

根因：`normalizeMgmtSubPath` 只用 `url.Parse(req.Path)` 取查询串，而宿主下发管理请求时**可能只给纯路径**，查询参数单独放在 `req.Query`；原代码还用 `_ = urlQuery` / `_ = req.Query` 把两者显式忽略掉了。

修复：新增 `mergeRequestQuery(pathQuery, hostQuery)` 合并两个来源，宿主下发值优先；删除两行占位忽略。

## 八、注意

1. 积分快照是**实时拉取**（每次 `/credits` 都回源 `/user/info`），未做缓存；账号多时面板会并发多次请求，若后续账号量上来需要加短 TTL 缓存。
2. `left_score` 上游以字符串下发（`"199.01"`），面板按字符串展示，未做数值运算，避免精度与单位误判。
3. 该端点同时是「识别访客账号」的入口（`is_guest` 字段），后续如需在面板标注访客账号可直接复用同一响应。
