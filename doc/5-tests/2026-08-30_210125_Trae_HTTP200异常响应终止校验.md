# Trae HTTP 200 异常响应终止校验

结论：`qwen3.8-max` 上游可持续输出 107.164 秒并以 `done -> EOF` 完成；TraeWork 已改为实时读取，且只有收到 `done` 才判定成功。影响：长回答不再等待完整响应后集中回放，部分输出后 EOF 会返回截断错误，最终 stop 下发失败不会记录成功。范围：异步宿主流桥、CPA callback context、三条 SSE 响应出口、用量核算和对应回归测试。非范围：本轮不修改账号重试预算、CPA 模型映射和 direct fallback 的 120 秒超时。变化：接入 `host.http.do_stream`，透传 `HostCallbackID`，收紧 done 终止契约。完成标准：cgo shim 的 build、vet、test、污染扫描、格式检查和 `6-review` 通过；CPA 本地入口恢复后补端到端长流验证。术语说明：`done` 是 Trae 明确表示生成完成的业务事件，EOF 只表示传输结束。验证状态：真实 Trae 上游与代码级验证通过；CPA OpenAI API 本地入口验证受服务不可用限制。

## 验证结论

- 代码级验证：通过。共享状态 `traeSSETerminal` 只有收到 `done` 才允许成功结束；`output -> EOF` 返回截断错误。
- 实时流桥验证：通过。callback wire、宿主 chunk 跨边界重组和最终 stop 下发失败核算均有回归测试。
- EOF 尾帧验证：通过。无换行 `done`、无换行 `output` 均可解析，只有 `event:` 的残缺尾帧不会触发业务事件。
- 模块验证：通过。`cgo-shim-build.py traework` 的 build、vet、test 均成功，最新用时 1.311 秒。
- 生产代码测试污染：通过。扫描 6 个变更文件，命中 2 个既有测试函数的 ORPHAN 提示，没有生产污染，输出 `POLLUTION: PASS`。
- 真实上游验证：通过。`qwen3.8-max` 持续 107.164 秒，收到 298 个 output、11,683 个字符、一个 done，终止为 `done -> EOF`。
- CPA 入口端到端验证：受限。本机 `127.0.0.1:8317` 没有可用 CPA 服务，尚未验证客户端首包、持续 chunk 与唯一 stop。
- 浏览器联调：N/A。原因：本轮未修改页面或管理接口；证据：变更位于 HTTP 流桥、SSE 解析和用量核算。

## 完成标准

1. 没有 `done` 的响应不会生成成功 completion 或 stop；部分 output 后 EOF 返回截断错误。
2. EOF 前没有换行的 `done` 或 `output` 行仍会被解析，孤立 `event:` 尾帧不会触发事件。
3. 异步请求透传 `HostCallbackID`，并能跨任意宿主 chunk 重组 SSE。
4. 最终 stop 下发失败不得复位账号或发布成功用量。
5. TraeWork 的 build、vet、test、污染扫描和格式检查通过；测试资产归位前 `6-review` 保持 `STYLE: FIX_REQUIRED`。
6. CPA 本地入口可用后补充端到端长流验证，当前受限状态不得写成生产放行。

## 本地授权与请求构造核验

- 验证环境：本机 Trae SOLO 的 `storage.json`。
- 授权前置：通过。本机存在 `iCubeAuthInfo://icube.cloudide` 授权条目；凭据以加密 `tc-header` 格式在内存中按插件同等的 AES 解密与完整性校验流程解析，未输出 credential、token、账号信息、请求头或模型正文。
- 请求构造：通过。`parseTraeAuth` 可解析授权存储内容；`buildTraePayload` 将最小对话组织为 `llm_utils_chat` 请求体；`callLLM` 使用 `https://trae-api-cn.mchost.guru/api/agent/v3/llm_utils_chat` 和 Trae 授权头构造请求。
- 动态模型目录：同一授权调用 `get_detail_param` 返回 36 个可用模型，包含 `qwen3.8-max`、`qwen-3.7-plus`，不包含 `qwen-max-latest`。
- 真实流式推理：已执行。

| 场景 | HTTP / 内容类型 | SSE 事件 | 输出与终止 | 结论 |
| --- | --- | --- | --- | --- |
| `qwen3.8-max` 短请求 | 200 / `text/event-stream` | `metadata -> timing_cost -> output × 4 -> extra_info -> token_usage -> done` | 79 字符、1.7 秒、收到 done | 真实流式推理完成 |
| `qwen3.8-max` 长请求 | 200 / `text/event-stream` | `output × 298`，最终 done | 11,683 字符、107.164 秒、`done -> EOF` | 上游可持续长流，未出现 SSE error |

长请求首事件在 1.152 秒到达，最大事件间隔 1.951 秒。`qwen-max-latest -> qwen3.8-max` 的映射由 CPA 完成，本轮排查以 TraeWork 实际发送的 `qwen3.8-max` 为准，不再使用别名直连失败解释生产断流。
