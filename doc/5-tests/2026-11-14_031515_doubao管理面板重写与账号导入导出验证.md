## 3. 变异与反证

- **导出必须原样回写物理字节**：`TestHandleExportAccountsZipRoute` 解 ZIP 后逐字节比对 `rawCredentialBytes` 结果，确认不是重新 `json.Marshal` 的产物；若改成重新序列化，未知字段与键序会丢失，`TestHandleExportAccountsRoute` 的回灌断言随之失败。
- **导出 → 导入闭环真实成立**：`TestExtractImportPayloadShapes` 的第四形态直接喂 `handleExportAccounts` 的完整输出，断言能取出与原账号一致的 cookie —— 这是闭环的反证，不是形态枚举的装饰断言。
- **新增测试真实进编译**：临时插入 `TestSentinelMustFail`，shim 输出 `FAIL` 且打印「哨兵失败：export_test.go 已进入编译」；删除后复绿，证明 `export_test.go` 不是仅存在于磁盘。
- **面板脚本不是「看起来对」**：`node --check` 在临时目录跑（不能在 `F:\cpa-plugin` 下跑，仓库根 `package.json` 非法会报 `ERR_INVALID_PACKAGE_CONFIG`），两个 script 块均 `exit=0`；再以 id / 引用差集与 handler / 定义差集双向校验，`MISSING=[]` 才放行。
- **密钥零输入的根因方向被验证**：旧面板只有 `enc::v1::` 且无脏值清理，与 workbuddy 的 `enc::v2::` 分支缺失一致；新面板 `deobfuscate` 先 v2 再 v1，`readSessionKey` 遇 `enc::` 前缀脏值主动清除，与兄弟插件九个面板的密钥段逐字对齐。
- **删除掉的是真未用代码**：`#refreshProgress`、`.toggle`、`.badge.stat` 删除后复跑 id / handler 交叉校验与 CSS 使用扫描，`MISSING=[]`；剩余 `cntAll` / `exportBtn` 等「未引用」项均由 JS 字符串拼接或 CSS 选择器使用，属扫描误报。
