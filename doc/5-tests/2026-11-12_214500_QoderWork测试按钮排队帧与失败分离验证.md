## 1. 结论

三条链路全绿：新增 7 个测试全部 `--- PASS`，`cgo-shim-build.py qoderwork` build / vet / test 全绿，面板两段 script 语法校验 `blocks=2 bad=0`。**两类反证均按预期失败并复原**：哨兵输出 `SENTINEL-ALIVE: waitSeconds() = 60` 且 `--- FAIL`；变异（把 `parseQueueFrameInfo` 命中条件改成恒假）使 shim `FAILED: go test (exit 1)`，证明新测试真的锁住了排队解析分支而不是空跑。非排队失败文案经 `TestBuildActivePingFailureNonQueueUnchanged` 锁定为逐字不变。

## 2. 变更目标

| 维度 | 变更前 | 变更后 |
|---|---|---|
| 排队帧错误类型 | 普通 `fmt.Errorf`，与 401/112 混同 | 专用 `*queueFrameError`（`errors.As` 可取），`Error()` 文本不变 |
| 面板结果 map | `{error, model}` | 排队时额外 `upstream_queued`/`detail`/`retry_after_seconds`/`queue_type`/`queue_count`/`sub_code`/`upstream_model` |
| 用户看到的文案 | `活跃测试失败 (模型: X): upstream 200: 403: 10605: {&#34;...` | `上游排队中 (模型: X，队列 p4，前方 1 个请求)，约 60 秒后可重试；账号与凭据正常，属上游容量排队而非测试失败` |
| 面板态 | 两态（成功/失败） | 三态（成功/排队 warn/失败 err） |
| 排队判定与 failover | 已正确 | 零改动 |
