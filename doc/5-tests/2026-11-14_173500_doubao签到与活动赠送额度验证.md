## 8. 生产实测：0.1.12 暴露判据顺序缺陷，0.1.13 修复

### 8.1 0.1.12 生产实测结果（2026-11-14 17:47，`GET /checkin/status`）

生产共 12 个 doubao 账号，仅 2 个状态正确：

| 账号 | 0.1.12 状态 | 真实情况 |
|---|---|---|
| 欧皇小德子 | `done` / 今日已签到 / `chosen_type=0` / 额度 200/200（100%） | 正确 |
| 用户158477 | `desktop_only` / 需桌面端领取 / `chosen_type=3` | 正确 |
| 号10 / 用户358840 / 用户288838x / 第七 / 用户220908 / 用户766588 / 用户815917 / 用户825285 / 用户305270 / 用户224666 | `error` + 「签到活动已下线或已换季」 | **误判**，实际均为 `chosen_type=3` 需桌面端 |

### 8.2 上游取证（生产宿主机直连）

| 账号 | `POST /alice/ug/campaign/v3/detail/` | `POST /alice/ug/campaign/landing/get` |
|---|---|---|
| `doubao-adcd31d29873b4c8.json`（欧皇小德子） | `code=0`，`data` 含 `tasks` / `example_cases` | `{"data":{"chosen_type":0,"landing_cards":[]},"code":0}` |
| `doubao-20fcbcfb49f40321.json`（号10） | `{"data":null,"code":2,"msg":"","message":"campaign not found"}` | `{"data":{"chosen_type":3,"landing_cards":[{"card_code":"web_pc_download_banner",...,"content":"下载桌面端"}]},"code":0}` |

结论：桌面端渠道账号在网页侧没有活动实例，`v3/detail` 必然回 `code=2`，**只有 `landing/get` 的 `chosen_type` 是渠道真相源**。0.1.12 先查详情、详情非 0 即失败的顺序把这 10 个账号错报成活动下线。

### 8.3 修复内容（0.1.13）

`checkinStatusFor` 与 `runCheckinForAccount` 判据顺序统一改为：

1. 登录态（失效即 `expired`，不打上游）
2. **落地页 `chosen_type` 先行**——非 `checkinChosenWeb` 直接 `desktop_only` 返回，不请求详情、不产生写请求
3. 网页渠道才拉 `v3/detail`
4. 三态判定（`checkinStatusFor`）/ 已签短路（`runCheckinForAccount`）
5. 额度降级（`quota_error`）；`runCheckinForAccount` 的第 5 步为提交后回查确认

### 8.4 回归验证

- 新增 `TestCheckinStatusForDesktopAccountIgnoresDetailError`：桩 `v3/detail` 回 `code=2 campaign not found` + `landing/get` 回 `chosen_type=3`，断言 `state=desktop_only`、`chosen_type=3`、**未请求 `checkinDetailPath`**、未请求 `checkinRunPath`。
- `TestRunCheckinSkipsWhenAlreadySigned` 补显式 `checkinLandingPath: checkinLandingWebBody`，避免新顺序下靠默认空响应蒙对。
